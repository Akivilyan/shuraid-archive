# 内容迁移门禁

## 原则

旧工程 `M:\codex\ShuRaid` 是候选来源库，不是需要整体搬迁的项目。每次迁移必须服务于当前正在实现的一个明确对象，并记录来源、用途、目标路径和验证结果。

禁止为了“以后可能会用”而提前复制资源。

## 阶段

### 0. 空工程基线（当前）

允许：

- 游戏设计文档；
- 视觉方向文档；
- 本迁移门禁与项目交接。

禁止：

- 所有图片、音频、脚本、场景、Prefab 和旧配置。

完成条件：Cocos 编辑器正常识别官方空项目，并完成空场景的微信小游戏 Release 性能基线。

### 1. 第一个人物

只选择一名已确认人物。先确认实际需要的待机、移动、攻击和受击帧，再迁入对应文件。使用编辑器 SpriteFrame、AnimationClip 和 Prefab 工作流，不运行时切图。

### 2. 第一张场景

只迁入当前画面实际可见的背景和必要前景元素。未出现在当前场景中的营地、界面稿、候选背景和装饰不迁入。

### 3. 第一个敌人和攻击反馈

只迁入一个敌人的必要动作与当前人物的一个攻击效果。先完成对象池、命中范围一致性和真机性能验证，再增加第二类对象。

### 4. 音频与后续内容

仅在对应玩法已经可操作后迁入所需的一条 BGM 或单个 SFX。其余人物、敌人、技能和界面继续逐项过门禁。

## 每次迁移检查

- 当前功能是否马上使用该文件；
- 是否存在更小的必要文件集合；
- 是否错误携带旧 `.meta`、构建产物或过程稿；
- 是否通过 Cocos 编辑器正式导入并生成新 `.meta`；
- 是否完成编辑器预览、微信开发者工具和真机中与本阶段相称的验证。
