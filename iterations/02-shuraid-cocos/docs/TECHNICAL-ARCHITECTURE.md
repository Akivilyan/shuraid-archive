# Cocos 技术架构

## 目标

用 Cocos Creator 3.8.8 的场景、Prefab、Sprite、Animation、Tween、对象池和合批能力重新实现客户端。引擎负责表现和生命周期，确定性规则层负责玩法；不把旧 Canvas 主循环改名后塞进一个巨型组件。

## 目录与所有权

| 目录 | 所有权 |
| --- | --- |
| `assets/scripts/core/` | 纯规则、配置、状态、命令、事件；不得 import `cc` |
| `assets/scripts/game/` | 固定步长、场景组装、局内流程、系统调度 |
| `assets/scripts/presentation/` | 节点同步、动画、特效、音频、HUD、对象池 |
| `assets/scripts/platform/` | 微信生命周期、触摸、安全区、振动和设备适配 |
| `assets/art/runtime/` | Cocos 可直接导入的压缩运行资源 |
| `art-source/` | 不由 Cocos 导入的母图、拆帧和视觉参考 |

## 规则接口

规则层接收命令并推进固定步长，输出只读快照和一次性事件：

- 命令：移动向量、开始/暂停、技能选择；
- 快照：实体 ID、当前位置、朝向、生命、动画状态和局内阶段；
- 事件：攻击开始、命中、受伤、死亡、掉落、升级和战斗结束。

表现层不得直接改变规则实体。动画回调只可通知表现完成，不能决定伤害、冷却和生成。

## 帧循环

- 规则按固定 `1/60` 秒步长推进；
- 每帧限制最大补帧次数，防止退到后台后出现“追帧风暴”；
- 渲染使用上一状态与当前状态插值；
- 微信 `onHide` 立即暂停并清空累积时间，`onShow` 等待用户恢复；
- 任何重新开局都必须由明确的战斗结束/重试命令触发，不能因大 `dt`、异常或组件重新启用自动重置。

## 性能规则

- 战斗开始前预热敌人、投射物、经验豆和常用特效对象池；
- 热路径禁止逐帧 `new` 数组/对象、闭包、字符串拼接和节点查找；
- 禁止在战斗循环中频繁 `new Node()`、`instantiate()`、`destroy()`；
- 相同材质和图集尽量连续渲染，控制 Draw Call；
- 不用逐帧 `Graphics` 绘制阴影、圆环和轨迹；
- 可见对象之外关闭动画和昂贵同步，但规则状态继续由核心层管理；
- 优化必须以微信真机性能面板数据为依据，记录机型、FPS、P95 帧耗时、Draw Call、节点数、纹理内存和脚本热点。

## 分阶段实现

1. 移动、固定步长、插值、一个敌人、一个普攻；
2. 受击、死亡、对象池、经验豆和稳定刷怪；
3. 升级暂停与三选一；
4. 关羽三项技能；
5. 黄忠投射物族；
6. 诸葛亮闪电与区域技能；
7. 完整波次、首领、音频；
8. 首页、武将页和设置。

每阶段都必须先通过微信真机移动流畅度和稳定性，再扩大范围。
