# 报，蜀军来劫粮：项目交接

更新日期：2026-08-09
状态：当前开发入口，新任务应先读本文，再检查代码与测试。本文与旧设计文档冲突时，以本文和当前代码为准。

## 1. 项目目标

这是一个面向微信小游戏的轻量三国 Roguelite 原型，核心参考《弹壳特攻队》一类自动攻击生存玩法：玩家只负责移动，在局内通过升级三选一取舍技能，逐渐形成角色构筑。

当前阶段只证明三件事：

1. 使用 Codex 能否高效完成一款可在微信真机运行的小游戏；
2. 三种基础攻击模型能否支撑不同武将与一至两个清晰流派；
3. 技能选择与组合能否比单纯走位更有吸引力。

项目坚持个人开发者可控体量。优先做出好玩的战斗循环和足够讨喜的“游戏皮”，不追求企业级健壮性，也不堆叠复杂系统。

## 2. 当前已确认的产品边界

- 竖屏、单指移动、自动索敌和自动攻击；
- 一局约 3.5 分钟后刷出首领，实际结束时间取决于击杀速度；
- 局内升级三选一，最高 12 级；
- 每名武将一个固有技能、三个专属技能，另有三个通用被动；
- 单局最多持有两个额外主动技能和两个被动；
- 所有可选技能满级后，继续升级会少量回血并自动恢复战斗，不允许出现空白选择页；
- 暂无局外成长、碎片、广告、支付、排行榜、账号、联网或云开发；
- 武将碎片与等级是未来可能加入的第一层局外成长；刘备、诸葛亮阵营科技树只保留为远期扩展，不进入当前版本。

### 诸葛亮当前技能

- **闪电链**：首击只搜索 300 像素内且位于当前画面的敌人；没有有效目标时不播放攻击动作和音效，也不消耗攻击冷却；从诸葛身体连接到首个目标；每 0.1 秒继续弹射；单跳约 176 像素，整条链限制在诸葛周围约 330 像素；伤害逐跳衰减。
- **闪电连击**：将总弹射次数按等级改为 5、7、9 次；连同初始固有技能构成 3、5、7、9 的成长序列。优先选择未命中的目标，无新目标时才允许在存活敌人之间往返弹射，且不立刻打回刚离开的目标。
- **八阵图**：每 4.2 秒投向 360 像素内最密集敌群；范围随等级增加，造成范围伤害；阵图显示持续 1.5 秒。最新表现为金色八边阵门、八组卦爻、内层八门和阴阳核心。
- **东风摧阵**：固定 210 像素范围、固定强击退并造成 5 点固定伤害；普通敌人推力 900，首领承受 35%；三级冷却为 8、6.75、5.5 秒，风效显示持续 1.05 秒。最新表现取消白色圆阵，改为向外扩散的青绿色风流、风矢和微粒。

所有敌人受到攻击后固定减速 12 点，持续 2 秒，最低移动速度为 18。再次受击只刷新持续时间，不叠加减速层数或幅度；统一通过 `hitEnemy` 入口处理，不增加持续范围扫描。

用户已在 2026-08-09 确认诸葛亮的基本骨架与可玩性成立。除非收到新的明确试玩反馈，不再继续扩大诸葛技能范围或增加新机制。

## 4. 关卡、经验与性能边界

- 6 波固定时间轴；每波持续 30 秒，波间休整 5 秒；
- 各波计划敌人数：`30 / 42 / 54 / 66 / 78 / 90`，合计 360；
- 刷新间隔：`0.9 / 0.62 / 0.46 / 0.36 / 0.28 / 0.25` 秒；
- 第 210 秒刷出首领，之后不再生成普通敌人；
- 远程单位从后续波次正常混入，不设置额外数量上限；
- 同屏敌人安全上限为 78；
- 经验需求公式：`(4 + 2 × step + floor(step² / 4)) × 3`，其中 `step = level - 1`；
- 局内最高 12 级，满级后敌人不再掉落经验。

这些数值已经经过多轮体感调整。进行美术、动画和技能表现工作时不要顺手改动波次、总敌量或经验曲线。

## 5. 敌人方向与当前实现

最终美术方向不是严肃魏吴士兵，而是明亮、无厘头的“伙夫军团”，弱化暴力感。兵种辨识优先依赖外形、体积和携带物，阵营颜色不是主要规则。

计划保留 10 个普通兵种、4 个行为大类：骑兵、近战、盾兵、远程。不做治疗、增益、减益、作用域光环或复杂状态。

当前真正接入运行时的只有四种：

| 程序类型 | 当前美术 | 行为 |
| --- | --- | --- |
| `grunt` | 厨师长 | 普通追逐与接触伤害 |
| `runner` | 推灶车 | 高速追逐与接触伤害 |
| `brute` | 锅盖兵 | 高生命、低速接触伤害 |
| `archer` | 包子投手 | 保持距离并发射简单包子弹丸 |

首领目前只是加强参数和独立轮廓，尚未设计为魏、吴名将。其余候选包括烤乳猪骑兵、背锅兵、挑担兵、菜板兵、整根辣椒投手和鸡蛋投手，仍未接入代码。

## 6. 美术与动画方向

界面、战斗角色和技能特效的长期规则见 `docs/design/INTERFACE-VISUAL-STANDARD.md`。该文档是后续视觉迭代的直接约束，不再依赖聊天记录复述参考方向。

- 角色采用“襁褓豆脸”式原创 Q 版：大脸、短四肢、圆润身体、粗轮廓、明亮大色块；
- 主角用表情、帽冠、胡须、羽扇或武器建立辨识度；普通小兵重点保证地图缩小后仍能靠轮廓辨认；
- 人物中轴保持自然竖直，不因移动或索敌整体横倒；
- 首版动画只需要待机、移动、攻击/施法、受击；
- 当前采用离散 PNG 图集加 Canvas 轻量变换，不引入 Blender、3D 模型或复杂骨骼运行库；
- 美术生产采用“小批确认”：先做一个角色或一个兵种的样稿与动作组，试玩确认后再横向复制；不要一次生成全部角色。

运行时图集位于 `assets/runtime/`，高质量母图、拆帧和概念稿位于 `assets/sprites/` 与 `assets/concepts/`。上传包通过 `project.config.json` 排除源美术、文档、脚本和测试，只携带压缩运行资源。

## 8. 技术结构

- 微信小游戏根目录：项目根目录本身，`compileType` 为 `game`；
- 入口：`game.js`；平台循环：`src/platform/wechat-game.js`；
- 战斗规则：`src/core/world.js`；静态参数：`src/config.js`；技能表：`src/core/skills.js`；
- 绘制：`src/render/renderer.js`；轻量姿态：`src/render/character-rig.js`；
- 音频：`src/audio/audio-manager.js`；触控：`src/input/touch-controller.js`；
- 不使用第三方运行依赖，不使用 CloudBase；
- 保持传统 JavaScript 写法，避免可选链、空值合并等可能造成微信基础库兼容问题的语法；
- 高频战斗特效继续使用 Canvas 路径和固定上限，不引入无限粒子或复杂逐单位作用域扫描。
- Git 仓库根目录为项目根目录本身，默认分支为 `main`；`project.private.config.json` 属于本机微信开发者工具配置，不进入版本控制。

## 10. 已否决或暂缓的方向

- 不回到 EnergyCompany 式模拟经营体量；
- 不做大本营、刘备阵营 Buff、诸葛局外挂件或分支科技树；这些只保留远期可能性；
- 不做无限刷怪；关卡使用固定时间轴，清怪慢就自然积压并失败；
- 不让敌人总量过少，也不把远程敌人从波次中移除；
- 不把魏吴阵营颜色当成小兵的首要辨识方式；
- 不做兵种专属 Buff、治疗、光环和复杂减益系统；仅保留统一受击固定减速，持续时间可刷新但幅度不可叠加；
- 不照搬《弹壳特攻队》《不思议迷宫》《糖豆人》的具体资产，只吸收移动端可读性和亲和造型原则；
- 不为了“高级”引入 Blender 流程；当前图集质量能够运行就不反复主动降级。

## 11. 下一窗口的推荐顺序

1. 先运行 `npm test` 与 `npm run check`，确认基线；
2. 让用户试玩第一层界面：确认固定底栏、劫粮主页、直接换将、设置返回路径和真机安全区；
3. 只根据试玩反馈微调界面，不同时改波次、经验或武将数值；
4. 第一层稳定后进入第二层：让战斗角色身体保持稳定，以脚步和轻微起伏表达移动，自动攻击从固定锚点生成；
5. 第二层稳定后进入第三层：建立亮核、辉光、轨迹、命中爆发等统一技能特效层级，再逐个武将升级表现；
6. 三层骨架稳定后，回到关羽和黄忠的技能分工与正式图集，再按四类行为模型逐步接入其余伙夫兵种。
