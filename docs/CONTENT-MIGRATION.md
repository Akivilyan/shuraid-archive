# 内容迁移指南

## 原则

最高原则是敏捷开发、快速落地。本文件提供默认路线，不是刚性门禁。

旧 Canvas 工程 `M:\codex\GameOne\luanshi-survivor` 是已验证玩法、运行素材与显示参数的首要参考来源。旧资源可以按最快落地方式直接使用，不要求逐文件迁移、逐文件哈希或逐文件验证。

旧 Cocos 工程 `M:\codex\ShuRaid` 与 `M:\codex\ShuRaid-Cocos` 的脚本、场景、settings、旧 `.meta`、构建配置和 code-first 表现架构已经证明不适合当前项目，不整体复用。除此之外，不为资源迁移设置额外仪式。

## 参考顺序

以下只是内容展开顺序，可根据实现效率合并，不构成逐阶段验收门禁。

### 0. 空工程基线（已完成）

允许：

- 游戏设计文档；
- 视觉方向文档；
- 本迁移指南与项目交接。

禁止：

- 所有图片、音频、脚本、场景、Prefab 和旧配置。

完成条件：Cocos 编辑器正常识别官方空项目，并完成空场景的微信小游戏 Release 性能基线。

### 1. 第一个人物（当前，关羽表现层校正中）

只选择一名已确认人物。先检查旧版本实际加载的运行图集、源矩形、显示尺寸、枢轴和动作选择，再迁入对应文件。使用编辑器 SpriteAtlas、SpriteFrame、AnimationClip 和 Prefab 工作流，不在运行时切图。

关羽首轮六张独立 512×384 动作图虽然文件有效，但没有恢复旧版 384×288 图集帧及其显示契约，不能继续作为视觉比例基准。校正时优先使用旧 Canvas 实际加载的 `assets/runtime/guan-atlas.png`。

### 2. 第一张场景

只迁入当前画面实际可见的背景和必要前景元素。未出现在当前场景中的营地、界面稿、候选背景和装饰不迁入。

### 3. 第一个敌人和攻击反馈（基础逻辑已实现，等待关羽校正）

只迁入一个敌人的必要动作与当前人物的一个攻击效果。先完成对象池、命中范围一致性和真机性能验证，再增加第二类对象。

### 4. 音频与后续内容

玩法可操作后再加入当前批次需要的 BGM 或 SFX；若音频与角色、场景一起接入更高效，也可以合并完成。

## 快速检查

- 是否误带旧 Cocos 脚本、Scene、settings、`.meta` 或构建配置；
- 是否让 Cocos 编辑器正式导入资源并建立原生引用；
- 是否在一个有意义的可玩批次结束时集中构建和提交，而不是每个小改动都重复验证。
