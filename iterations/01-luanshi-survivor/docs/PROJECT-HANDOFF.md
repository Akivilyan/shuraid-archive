# 报，蜀军来劫粮：项目交接

更新日期：2026-08-10
状态：当前开发入口，新任务应先读本文，再检查代码与测试。本文与旧设计文档冲突时，以本文和当前代码为准。

## 1. 项目目标

这是一个面向微信小游戏的轻量三国 Roguelite 原型，核心参考《弹壳特攻队》一类自动攻击生存玩法：玩家只负责移动，在局内通过升级三选一取舍技能，逐渐形成角色构筑。

当前阶段只证明三件事：

1. 使用 Codex 能否高效完成一款可在微信真机运行的小游戏；
2. 三种基础攻击模型能否支撑不同武将与一至两个清晰流派；
3. 技能选择与组合能否比单纯走位更有吸引力。

项目坚持个人开发者可控体量。优先做出好玩的战斗循环和足够讨喜的“游戏皮”，不追求企业级健壮性，也不堆叠复杂系统。

## 2. 当前已确认的产品边界

- 竖屏、单指移动、自动索敌和自动攻击；
- 一局约 3.5 分钟后刷出首领，实际结束时间取决于击杀速度；
- 局内升级三选一，最高 12 级；
- 每名武将一个固有技能、三个专属技能，另有三个通用被动；
- 单局最多持有两个额外主动技能和两个被动；
- 所有可选技能满级后，继续升级会少量回血并自动恢复战斗，不允许出现空白选择页；
- 暂无局外成长、碎片、广告、支付、排行榜、账号、联网或云开发；
- 武将碎片与等级是未来可能加入的第一层局外成长；刘备、诸葛亮阵营科技树只保留为远期扩展，不进入当前版本。

### 诸葛亮当前技能

- **闪电链**：首击只搜索 300 像素内且位于当前画面的敌人；没有有效目标时不播放攻击动作和音效，也不消耗攻击冷却；从诸葛身体连接到首个目标；每 0.1 秒继续弹射；单跳约 176 像素，整条链限制在诸葛周围约 330 像素；伤害逐跳衰减。
- **闪电连击**：将总弹射次数按等级改为 5、7、9 次；连同初始固有技能构成 3、5、7、9 的成长序列。优先选择未命中的目标，无新目标时才允许在存活敌人之间往返弹射，且不立刻打回刚离开的目标。
- **八阵图**：每 4.2 秒投向 360 像素内最密集敌群；范围随等级增加，造成范围伤害；阵图显示持续 1.5 秒。最新表现为金色八边阵门、八组卦爻、内层八门和阴阳核心。
- **东风摧阵**：固定 210 像素范围、固定强击退并造成 5 点固定伤害；普通敌人推力 900，首领承受 35%；三级冷却为 8、6.75、5.5 秒，风效显示持续 1.05 秒。最新表现取消白色圆阵，改为向外扩散的青绿色风流、风矢和微粒。

所有敌人受到攻击后固定减速 12 点，持续 2 秒，最低移动速度为 18。再次受击只刷新持续时间，不叠加减速层数或幅度；统一通过 `hitEnemy` 入口处理，不增加持续范围扫描。

用户已在 2026-08-09 确认诸葛亮的基本骨架与可玩性成立。除非收到新的明确试玩反馈，不再继续扩大诸葛技能范围或增加新机制。

### 关羽与黄忠技能

技能名称与升级文案已按武将拆分到 `src/data/skills/`，技能池组装由 `src/core/skills.js` 负责，战斗执行仍位于 `src/core/world.js`：

- 关羽：青龙斩、青龙威势、偃月斩、温酒斩；
- 黄忠：强弓、连珠箭、破甲箭、箭雨；
- 通用被动：武勇、疾行、强身。

关羽已作为首个配置化和表现升级样板：`src/data/skills/guan.js` 集中保存固有攻击、两项固有攻击强化和保命技的每级数值与表现寿命；黄忠、诸葛亮目前已有独立技能清单，后续调整各自技能时再按相同结构迁入战斗数值，避免一次性重构成熟逻辑。

关羽当前规则以 2026-08-10 的试玩讨论为准：**青龙斩**是前方扇形普攻，基础半径 112、完整夹角约 55°；表现不直接填充扇形范围，而是让完整青龙偃月刀像展开折扇一样沿水平面扫过这段夹角，并留下短弧形斩痕；**青龙威势**同时温和增加扇面半径和夹角，三级最终为半径 130、完整夹角约 76°，始终小于 90°，不能扩成半圆或环身攻击；**偃月斩**保留为固定 10 秒冷却的 360° 保命技，三级范围 174，完整长柄青龙偃月刀以关羽握柄点为固定轴在 0.92 秒内严格旋转两周，并增加四道轻薄白色贝壳纹弧线；**温酒斩**让略透明的关羽分身冲向能覆盖最多敌人的直线，本体留在原地，三级冲击距离为 270/315/360、总判定宽度为 40/52/64，分身显示倍率为 1/1.14/1.28。温酒斩表现时长为 0.82 秒，使用匀缓推进、两个低透明残影和四条固定劲风线，残影不产生额外伤害。青龙斩和偃月斩的特效坐标在整个播放期间逐帧绑定关羽当前位置，移动中不得漂在释放时的旧地图坐标；温酒斩分身则保留释放时的起点独立冲出。青龙偃月刀透明母图为 `assets/concepts/guan-yanyuedao-master-v1.png`（1729×274），运行图为 `assets/runtime/guan-yanyuedao-v1.png`（1024×162），用于青龙斩与偃月斩。现有图集的攻击帧固定朝左，无法匹配任意方向自动索敌，因此关羽本体在自动技能发动时继续持刀跑步或待机，不切换攻击帧；攻击方向由独立武器与斩痕表达。无敌人进入普攻距离时，不播放攻击音效或空刀特效。旧版填充扇形提示面、直线巨刃、光束、宽刀气、旋风斩、青龙刀气、赤焰行军和赤兔疾驰不再沿用。

关羽与黄忠的战斗图集统一以角色脚底为基线：运行时图像底边落在角色局部坐标 `y=17`，影子中心为 `y=12`，保证脚部压住影子而不是悬浮在上方。后续替换图集时也要保持这一锚点关系。

这些技能目前能玩，但数值仍以试玩反馈继续调整。用户已明确：技能算法必须简单，深度优先来自取舍与组合，不来自复杂判定。

## 4. 关卡、经验与性能边界

- 6 波固定时间轴；每波持续 30 秒，波间休整 5 秒；
- 各波计划敌人数：`30 / 42 / 54 / 66 / 78 / 90`，合计 360；
- 刷新间隔：`0.9 / 0.62 / 0.46 / 0.36 / 0.28 / 0.25` 秒；
- 第 210 秒刷出首领，之后不再生成普通敌人；
- 远程单位从后续波次正常混入，不设置额外数量上限；
- 同屏敌人安全上限为 78；
- 经验需求公式：`(4 + 2 × step + floor(step² / 4)) × 3`，其中 `step = level - 1`；
- 普通敌人的经验豆数值统一为原来的两倍：厨师长 2、推灶车 2、锅盖兵 6、包子投手 4；经验豆数量和拾取逻辑不变；
- 局内最高 12 级，满级后敌人不再掉落经验。

这些数值已经经过多轮体感调整。进行美术、动画和技能表现工作时不要顺手改动波次、总敌量或经验曲线。

## 5. 敌人方向与当前实现

最终美术方向不是严肃魏吴士兵，而是明亮、无厘头的“伙夫军团”，弱化暴力感。兵种辨识优先依赖外形、体积和携带物，阵营颜色不是主要规则。

计划保留 10 个普通兵种、4 个行为大类：骑兵、近战、盾兵、远程。不做治疗、增益、减益、作用域光环或复杂状态。

当前真正接入运行时的只有四种：

| 程序类型 | 当前美术 | 行为 |
| --- | --- | --- |
| `grunt` | 厨师长 | 普通追逐与接触伤害 |
| `runner` | 推灶车 | 高速追逐与接触伤害 |
| `brute` | 锅盖兵 | 高生命、低速接触伤害 |
| `archer` | 包子投手 | 保持距离并发射简单包子弹丸 |

首领目前只是加强参数和独立轮廓，尚未设计为魏、吴名将。其余候选包括烤乳猪骑兵、背锅兵、挑担兵、菜板兵、整根辣椒投手和鸡蛋投手，仍未接入代码。

## 6. 美术与动画方向

界面、战斗角色和技能特效的长期规则见 `docs/design/INTERFACE-VISUAL-STANDARD.md`。该文档是后续视觉迭代的直接约束，不再依赖聊天记录复述参考方向。

- 角色采用“襁褓豆脸”式原创 Q 版：大脸、短四肢、圆润身体、粗轮廓、明亮大色块；
- 主角用表情、帽冠、胡须、羽扇或武器建立辨识度；普通小兵重点保证地图缩小后仍能靠轮廓辨认；
- 人物中轴保持自然竖直，不因移动或索敌整体横倒；
- 首版动画只需要待机、移动、攻击/施法、受击；
- 角色继续采用离散 PNG 图集，不引入 Blender、3D 模型或复杂骨骼运行库；正式运行表现转向 Cocos Sprite、节点枢轴、Tween 与对象池；
- 美术生产采用“小批确认”：先做一个角色或一个兵种的样稿与动作组，试玩确认后再横向复制；不要一次生成全部角色。
- 武将立绘采用娱乐向英雄主视觉：画面需要达到精美、华丽的角色展示规格，同时用一本正经的角色与荒诞行为形成笑点。当前定稿锚点为关羽骑呆萌火焰赤兔、黄忠射小鸡、诸葛亮在路旁指挥苦哈哈木牛流马运输队；立绘与小型战斗图集分开生产。

运行时图集位于 `assets/runtime/`，高质量母图、拆帧和概念稿位于 `assets/sprites/` 与 `assets/concepts/`。上传包通过 `project.config.json` 排除源美术、文档、脚本和测试，只携带压缩运行资源。

- 三名首发武将均已有独立高精立绘并接入界面：关羽母图 `assets/concepts/hero-guan-red-hare-showcase-v4-legs-fixed.png`，黄忠母图 `assets/concepts/hero-huang-chicken-showcase-v1.png`，诸葛亮母图 `assets/concepts/hero-zhuge-wooden-ox-convoy-showcase-v2-candidate.png`；运行时分别使用 `assets/runtime/guan-showcase-v1.jpg`、`huang-showcase-v1.jpg`、`zhuge-showcase-v1.jpg`。劫粮主页、全屏武将页和底部换将缩略卡共用这些运行时图；
- 设置支持振动、音乐和音效开关；
- 升级选技不能在 `touchstart` 阶段直接确认：面板出现后有 240 毫秒防误触期，并且必须由面板出现后的全新触点在同一张技能卡内按下、抬起才选择；旧摇杆触点的抬起、鼠标悬停、滑出卡片和 `touchcancel` 均不得选中技能；

- 已有攻击、射击、敌人受击、玩家受击、拾取、升级、胜利、失败和危险提示音效；
- 音乐切换和音效逻辑已验证，但打击音质与细腻度仍有提升空间。

## 8. 技术结构

- 当前客户端主线：`cocos-client/`，固定使用 Cocos Creator 3.8.8；场景为 `assets/BattleSlice.scene`；
- Cocos 规则切片：`assets/scripts/BattleModel.ts`；场景调度：`BattleRoot.ts`；角色同步与敌人对象池：`ActorPresenter.ts`；技能特效池：`CombatVfxPool.ts`；共享 Sprite 构造：`ViewPrimitives.ts`；
- Cocos 战斗主路径不再使用 `Graphics`，引擎设置也已关闭 `graphics` 模块；敌人和三类技能特效在资源加载后预热，战斗中不创建、销毁节点；
- 阴影、青龙斩弧光、偃月斩环光、温酒斩风线共用 `assets/resources/art/battle-fx-atlas.png`；偃月刀以握把为枢轴旋转，青龙斩和偃月斩在播放期跟随关羽；
- 旧 Canvas 微信小游戏入口仍是 `game.js`，平台循环为 `src/platform/wechat-game.js`，绘制为 `src/render/renderer.js`。它只作为尚未迁移内容与规则对照，不再作为新表现功能的开发目标；
- 完整规则当前仍以 `src/core/world.js`、`src/config.js`、`src/data/skills/` 和既有测试为权威；不得为了删除 Canvas 而先删掉尚未迁入 Cocos 的黄忠、诸葛亮、波次、升级、音频与界面规则；
- 不使用第三方运行依赖，不使用 CloudBase；
- 保持传统 JavaScript 写法，避免可选链、空值合并等可能造成微信基础库兼容问题的语法；
- 微信小游戏运行时不会像 Node 一样可靠地把目录引用自动解析到 `index.js`；跨目录加载技能配置必须显式使用 `require("../data/skills/index")`；
- Git 仓库根目录为项目根目录本身，默认分支为 `main`；`project.private.config.json` 属于本机微信开发者工具配置，不进入版本控制。

## 10. Cocos Creator 主线重构决策

客户端表现正式以 **Cocos Creator 3.8.8** 为主线。目的不是指望更换引擎自动产生高级美术，而是使用稳定的节点锚点、Tween、Sprite 合批、对象池和特效分层工作流，停止继续扩展 Canvas 手写轨迹、残影和跟随关系。

### 迁移边界

- 第一块 Cocos 原生垂直切片已经完成：关羽、一种伙夫敌人、一段可反复进入的战斗，以及青龙斩、偃月斩、温酒斩三项表现；主页默认展示，必须点击“出阵劫粮”后才开始战斗。
- 原先 `BattleRoot.ts` 中的动态 `Graphics.clear()/arc()/ellipse()`、战斗中 `new Node()`/`destroy()` 和临时克隆节点已经删除；替代方案是共享 Sprite 图集、预热 `NodePool` 和 Tween 枢轴动画。
- 运行时切分的 SpriteFrame 与内置纯色帧必须保持 `packable = false`；否则 Cocos 动态小图合批器会再次打包内存纹理，在 WebGL2 下触发逐帧 `texSubImage2D` 异常并造成黑屏/严重卡顿。
- 玩法规则、伤害范围、冷却、索敌和击退仍由确定性模型负责，Cocos 组件只消费状态和事件；不要把规则散写进动画回调。
